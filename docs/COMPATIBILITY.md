# Codex 更新后的兼容性维护

本项目依赖官方客户端的页面结构。Codex 更新可能改变类名、窗口布局或渲染行为；自动测试只能覆盖已知契约，实际界面验收仍然必需。

## 当前已经具备的保护

- 官方 Store 包、可执行文件、回环监听归属和浏览器身份校验，阻止注入到错误进程。
- 保存注入器 PID、启动时间和命令行；已确认 PID 被复用时保留新进程并继续启动，身份未知时保留状态供排查。
- 壁纸就绪检查要求真实视频播放且解码帧增长；启动失败时保留工作，并避免重复激活已经启动的客户端。
- 安装更新保留文件备份；主题、个人媒体和运行状态留在本机。
- GitHub 的 Package checks 工作流在推送和 PR 时执行 Windows 包测试；它不安装或启动真实 Codex。

## 每次官方更新后的流程

1. 记录官方完整版本，先用普通启动入口确认 Codex 本身可用。不要在工作进行中强制退出进程。
2. 保存工作后完整退出，再从动画入口冷启动；检查只有一个工作窗口、动态壁纸连续播放、日志没有普通窗口回退。
3. 检查首页、对话页、菜单和输入区；特别看标题栏、侧栏接缝和底部是否多涂一层颜色。再检查侧栏收起/展开、缩放和窗口重开。
4. 出现偏差时，读取安装目录的 `logs/skin-handoff.log`、`logs/skin-watcher-error.log`、`qa/last-skin-ready.json`。先区分身份校验、视频解码和 CSS 适配问题，再修改对应层。
5. CSS 优先使用语义明确的 `data-*` 属性；必须兼容类名时保留新旧规则，并限定 Windows/窗口类型/输入区等范围。不要为一个截图把所有背景或所有子元素设为透明。
6. 更新源码后生成清单，运行 `scripts/Test-Package.ps1`；在目标官方版本进行真实界面验收，记录版本、测试范围和局限。通过后才部署并保留上一份文件。

自动发现新版并不代表新版已验证。当前没有自动巡检、版本兼容性数据库或自动下载远程修复；不要把这些当成已经实现的能力。

## 失败时回退

运行安装目录的 `Normal-Startup.cmd` 切换普通启动模式，恢复使用后再排查。需要恢复安装时的入口和外观，可使用 `Uninstall.cmd`。还原旧文件前保留当前配置；官方页面结构已变化时，旧版本本身也可能不兼容。

维护时不关闭签名、进程身份或回环限制，不修改 WindowsApps，也不根据远程未校验内容自动执行修复。故障日志和截图可能含本机路径或聊天内容，公开 issue 前应脱敏。

## 后续适合增加的功能

- 本地兼容性诊断：汇总官方版本、关键结构是否命中、视频解码和最近失败原因，输出可脱敏报告。
- 已验证版本与测试范围记录：让用户知道当前版本是否经过验证，而不是仅按版本号一概拒绝启动。
- 可选的更新前备份与一键恢复：先校验补丁和备份，再切换版本；测试失败时保留普通启动入口。

以上三项是后续建议，本次提交仅增加维护文档和现有包检查的自动执行。
